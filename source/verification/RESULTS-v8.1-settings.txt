Migration test coverage
-----------------------
Tests compile the actual new F2CacheMigration.h and actual F2PreferenceFile.h.
They use real temporary directories/files on the POSIX branch. They verify:
- no folders/files created when neither current nor legacy cache exists;
- staged copy, byte readback, old copy retained, repeat migration skipped;
- current-copy precedence, even when legacy is invalid or a dangling symlink;
- independent catalogue/reference migration and no nested content-mod settings;
- untouched user configuration, Favorites, authored assets and authored spawns;
- failed injected validation/readback, oversize limits, regular-file/path errors;
- symlink/dangling-symlink rejection and non-destructive directory handling;
- competing .pending file, concurrent copies, destination-created-mid-copy race;
- normal subsequent updates still replace only the settings-folder cache.

The migration validator in these tests is injected, not the production JSON
codec. Production parsing/DecodeEntries wiring was source-reviewed and checked
statically, NOT compiled here. Windows CreateFileW/MoveFileExW behavior, real
HostServices/UE4SS paths, full JSON integration and in-game migration are NOT
executed by these tests. The new create-only Windows path deliberately omits
MOVEFILE_REPLACE_EXISTING; this has not been tested against the Windows kernel.

Unchanged behavior
------------------
No UI rendering code changed, so no new rendering claims or screenshots are
made. Existing layout PNGs are offline v8 renders, not current game screenshots.
Refresh/progress/paging, badge paths, runtime attribution, native asset checks,
per-player features, network defaults and authored-mod destinations are unchanged.
The older schema audit remains out of scope.
