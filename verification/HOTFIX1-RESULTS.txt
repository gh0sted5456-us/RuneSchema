FOCUSED C++ COMPILER REGRESSION
This extracts the actual default-object if statement from QuickMenuCatalog.inl
and compiles it with small test-only UObject, UClass and TObjectPtr stand-ins.
The original expression (without .Get()) is compiled as a negative control and
must fail. The new expression must compile, have raw-pointer type, preserve
object identity, retrieve the default once, avoid null/lifecycle-invalid values,
and leave the mock object's fields unchanged.

This is NOT a UE4SS-header/native-ABI/MSVC test and is NOT a game test.

Commands (run from the package root):
  python verification/check_default_object_pointer.py --compiler g++
  python verification/check_default_object_pointer.py --compiler clang++ --sanitize

PACKAGING
The packaging script verifies the original archive's checksums and CRCs,
requires exactly the two source changes listed above, regenerates the manifest,
verifies every new archive entry, checks that no BAT is included, and performs
a temporary direct-merge simulation preserving unrelated source files and a
sentinel Build RuneSchema.bat. The SHA256-v6-F2.txt file covers every other entry.

LIMITATIONS
The full Windows DLL has NOT been built or linked here. Native UE4SS class,
property and asset interactions and all in-game/save behaviour remain untested.
Portable tests do not prove that every AI/resource definition is discoverable.
This fix addresses the reported compile errors, not a certification that no
further compiler errors exist in source files not covered by this overlay.
