# Core1 dependency boundary

RuneSchema still requires UE4SS for reflection, objects, lifecycle hooks, output and its GUI. The JSON core is a static library, not another runtime DLL. It provides JSON/JSONC file reading, primitive value checks, patch-envelope/selector validation and merge behavior without engine headers. Existing equipment/preset validators are also exercised by the standalone test build. Unreal FVector/FRotator/FName conversion, reflected property validation and application remain game-dependent.

Direct UE4SSProgram.hpp inclusion is confined to Runtime/HostServices.cpp for working directory and GUI setup. The adapter retains the existing UE4SS ImGui initialization macro and timing; it is not a new boot gate or GUI fix. Removed unused host-header includes from FileWatchWrapper, DragonWildsModLoaderBase and Spawn/RuntimeSupport. No speculative allocator, loader-order or hook changes were made.

The verified local pipeline explicitly links UE4SS's import library, freshly rebuilt Zycore/Zydis/SafetyHook/efsw/fmt/ImGui, RuneSchemaJsonCore and kernel32. Thirty-six unused explicit entries were removed, including separate Lua, Unreal helper, parser, assembler, graphics-backend and redundant Windows library inputs. Several had already contributed no code, so do not attribute all size savings to removing their names. Windows/CRT imports and the UE4SS dependency remain. The top-level upstream CMake route can still propagate extra transitive libraries; the reduced local pipeline is the route validated here.

The six static libraries are rebuilt from recorded local source snapshots with MSVC and /MD. The source/header lock fingerprints ten dependency trees (3,986 files); builds fail on drift rather than silently mixing headers and binaries. Its absolute paths reflect this workstation's cache, not a portable vendor bundle. The fmt tree contains a preserved check-macro push/undef/pop compatibility patch. Glaze's stale top-level pin was aligned to the actual tested local revision 3a850807501d98d23bab4bdc5af64d8d4e83e6bc. No installed UE4SS runtime was rebuilt. Its ABI compatibility remains a live-test requirement beyond import-name checks.

The dependency build retains a SafetyHook C4834 warning in utility.cpp: its destructor ignores the result of restoring memory protection. This pre-existing upstream behavior was recorded, not suppressed or changed during the dependency-boundary refactor. RuneSchema compiled with zero warnings/errors.

## Comparison research

[PalSchema's current build file](https://github.com/Okaetsu/PalSchema/blob/main/CMakeLists.txt) directly links Zydis, Zycore, SafetyHook, nlohmann-json, Glaze, UE4SS and efsw. Its [entry point](https://github.com/Okaetsu/PalSchema/blob/main/src/dllmain.cpp) derives from CppUserModBase, prepares signatures/offsets in construction and initializes the main loader in on_unreal_init. It remains UE4SS-based; it is not evidence that removing that host is trivial. [UE4SS's C++ mod guide](https://docs.ue4ss.com/guides/creating-a-c%2B%2B-mod.html) likewise uses the host lifecycle and import target. These references inform boundaries, not claims that their startup or shutdown is bug-free.

The user-supplied CreativeMenu 1.0.5 ZIP was inspected offline, not executed or installed. It contains CreativeMenu/dlls/CreativeMenu.dll (1,423,360 bytes), version.dll (351,232 bytes) and version_config.json. The config names CreativeMenu.dll as a load target; version.dll exports version-API functions, consistent with a proxy loader. Both binaries have Windows imports and no direct UE4SS import. CreativeMenu.dll imports dynamic-library lookup functions, so an import table alone cannot exclude dynamic dependencies or establish its internal SDK/allocator/hook safety. No source was available. Do not substitute its version.dll into RuneSchema or assume an equivalent standalone framework has been audited.

## Validation limits

Core1: 2,690,048 bytes versus installed LoadTight1's 3,283,456 (593,408 bytes smaller, about 18%). The reduction combines fresh dependency optimization, code organization and linking changes; no single cause was isolated. All 203 UE4SS imports resolve. Four standalone suites pass, covering file/comment parsing, deterministic file order, rejected malformed patches/selectors, protected identities, equipment compatibility and preset bounds. Source checks preserve patch bodies and normalize host-adapter substitutions against the baseline. CRT initializer pointer slots changed from 114 to 112; static initialization was not eliminated.

No Core1 game launch, world entry, GUI interaction, normal exit or server test has run. This is a candidate, not a heap-crash fix. Installed LoadTight1 and game content remain untouched. Preserve that baseline for a controlled comparison.
